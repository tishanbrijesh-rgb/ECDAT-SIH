# Phase 5 Gate — 2026-09-20

## Status

Phase 5 implementation is complete. The public-pilot release gate remains
pending because Docker is not installed on this workstation and remote CI has
not executed the current uncommitted working tree.

## WP-5.1 — Aligned and locked dependencies

- CI and the production image use Python 3.11, matching the backend base image.
- `backend/requirements.lock` contains the resolved Python 3.11 graph with
  package hashes; CI and Docker install it with `--require-hashes`.
- The Python and PostgreSQL release images are pinned by multi-platform digest.
- CI runs mandatory high-severity Bandit and strict pip-audit checks.
- Backend and scanner mypy scope is explicitly checked in CI.
- Local security proof: pip-audit and npm audit found zero known vulnerabilities;
  the high-severity Bandit gate passed after excluding detector fixture corpora.

## WP-5.2 — Benchmark and calibration automation

- Removed the invalid pre-production artifact download.
- The baseline comparison now explicitly downloads the artifact produced by its
  required corpus-evaluation job.
- Calibration errors are no longer converted into successful jobs.
- Corpus and calibration artifacts are schema-validated and stamped with commit,
  workflow-run, and generation-time provenance before upload.

## WP-5.3 — Production operations

- `scripts/verify_compose.py` is a destructive-safe, randomly named disposable
  PostgreSQL rehearsal: build, migration, authentication, three scans, outputs,
  API restart, persistence verification, and isolated volume cleanup.
- CI now requires this rehearsal on Ubuntu with Docker.
- The production runbook documents backup/restore drills, secret rotation,
  bad-release rollback, stale-lease recovery, corrupt exports, service-level
  indicators, and load/soak evidence.
