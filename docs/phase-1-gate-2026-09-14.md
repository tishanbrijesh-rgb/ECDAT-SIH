# Phase 1 Gate — 2026-09-14

## Outcome

Phase 1 passes its technical gate on the current working tree. Work was split
across three agents with non-overlapping ownership and integrated only after
their focused red-green cycles passed.

## Delivered

- Correct rolling-window rate limiting with atomic in-process storage,
  trusted-proxy CIDR handling, accurate retry timing, and independent client
  plus normalized-account login buckets.
- Centralized typed settings with production readiness validation for auth,
  scan roots, CORS, limits, timeouts, correlator selection, and deployment
  mode. Invalid production configuration fails closed with generic responses.
- Secret-minimized scan-worker environments, bounded atomic worker artifacts,
  job-specific temporary output, process-group/tree termination, and
  control-plane-only persistence.
- Compose hardening with production mode, read-only filesystem, constrained
  tmpfs, dropped capabilities, no-new-privileges, and PID/CPU/memory/nofile
  limits.

## Remaining limitations

- The in-memory rate-limit store is safe within one process but needs a shared
  backend before multi-replica deployment.
- True per-worker network namespaces and separate OS identities require a
  dedicated worker service; the combined container cannot provide that
  boundary per subprocess.
- Authenticated axe pages still require supplied test credentials.
- Docker execution remains unavailable on this host; Compose was verified
  statically and by tests only.
